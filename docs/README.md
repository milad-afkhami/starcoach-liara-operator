# Documentation

[← Project overview](../README.md)

Read Service Watch as a **service-monitoring product**, then inspect the evidence and action contracts. A documented capability is not automatically a live-accepted integration.

## Reading paths

| Reader | Recommended sequence | Outcome |
|---|---|---|
| Judge or product reviewer | [Overview](../README.md) → [User guide](user-guide.md) → [Evaluation](evaluation.md) | Understand the workflow and its measured limits |
| First-time user | [Getting started](getting-started.md) → [User guide](user-guide.md) | Open a service, inspect evidence and run a bounded investigation |
| Developer | [Architecture](architecture.md) → [Reference](reference.md) → [API capabilities](api-capabilities.md) | Understand components, contracts and provider qualifications |
| Owner/operator | [Deployment](deployment.md) → [Live QA](insured-vibe-coding/test-plans/live-liara.md) | Prepare exact setup/actions and collect genuine provider evidence |
| Presenter | [User guide](user-guide.md) → [Demo](demo.md) → [Submission record](../submission.md) | Rehearse, record and verify the final delivery |
