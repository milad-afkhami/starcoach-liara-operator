# Evaluation and practical limits

[diagnosis.json](../results/diagnosis.json) records an actual isolated Codex run over eight separately labelled synthetic cases, with expected answers retained by the evaluator. All eight met their expected cause-family or abstention outcome. Eleven model calls took roughly10–22seconds per case on the inspected local runtime. The investigator has no write interface, and no application write occurred in that evaluation. These observations do not establish real-incident success, strategy optimality, production MTTR improvement or a different model’s accuracy.

The cases cover dependency response mismatch, process crash, dependency timeout, distracting unrelated deployment, failed observer authentication with a passing endpoint, stale logs, unknown metric units, and insufficient evidence. Truth is in the separate harness fixture and never sent as a scenario/expected-answer label in model evidence. Output schemas constrain read/action names and citations; independent code rejects stale generations, unsupported IDs and unenrolled repair actions.

[observation-baselines.json](../results/observation-baselines.json) examines the same inputs through HTTP-only and latest-release-only observation baselines. HTTP-only reports available endpoint status; release-only reports whether a fresh release payload exists. Neither supports a causal claim by itself. These deliberately restricted baselines have different output contracts, so we do not manufacture a comparative cause-accuracy percentage or claim to outperform an existing SRE product. The unrelated-release case is a useful example of why visible change needs discriminating evidence.

The actual local two-service and packaged-container runs exercise a genuine HTTP dependency contract, process liveness,502regression, build propagation, correlated logs and restored healthy source. Independent rendered QA includes real model work, cancellation, same-failure observation stability, material invalidation, multi-session isolation, watch stop/expiry, active-call restart, provider-access gaps and missing model configuration. See [the precise local ledger](insured-vibe-coding/test-plans/operator-ui.md) and [container evidence](qa-evidence/packaged-containers.json).

Actual account-specific inventory/log/release/metric contracts, two cloud baselines, independent cloud fault injection and the approved cloud repair still require [live acceptance](insured-vibe-coding/test-plans/live-liara.md). A locally built image or passing fake-provider test cannot close those rows. The provider readiness/build/original-symptom proof remains mandatory before a live recovery claim.
